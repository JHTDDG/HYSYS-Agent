# AI 化工反应器智能建模 —— 开发报告

## 1. 技术选型理由

| 选型 | 理由 |
|------|------|
| **Python + win32com 直连 HYSYS COM** | HYSYS 官方自动化接口，无需导出中间文件、无需 GUI 截图识别，建模-求解-读结果全在进程外完成；Python 生态对 COM（pywin32）与 Web（FastAPI）支持最全 |
| **FastAPI + 单页前端** | 内置数据校验与自动文档，一条 `python -m app.main` 即可起服务；浏览器界面满足"展示形式不限"，Live Demo 直观 |
| **LLM（OpenAI 兼容接口）+ 规则引擎双通道解析** | LLM 负责自由自然语言的理解与结构化；规则引擎（知识库匹配 + 正则抽取）兜底——LLM 不可用、调用失败或漏给反应时服务不中断，且规则通道对两个必测场景 100% 覆盖 |
| **统一 ModelingTask JSON 契约** | 解析层只产 JSON、适配层只认 JSON，新增反应走同一条流水线，从架构上保证"不能只支持两个固定场景"这条硬要求 |
| **结构化 RAG 知识库（9 条典型反应）** | 知识规模小且高度结构化，组分集合匹配比向量召回更准且零依赖；用于已知反应匹配、典型工况假设（带出处）、命名反应兜底、澄清增强 |
| **Mock 适配器** | 与 COM 适配器同一契约，无 HYSYS 环境也能联调全链路与冒烟测试（92 项断言） |

## 2. 系统架构

```
自然语言 → [解析层] LLM 解析 ─┐（失败/漏给反应→兜底）
            规则引擎（知识库+正则+守恒校验）┴→ selector 反应器选择（考核§8 规则代码化）
                     ↓ 统一契约 ModelingTask JSON
            [适配层] COM 适配器（真实 HYSYS）→ 失败且属降级白名单(cstr/pfr/gibbs) → Mock 降级（明确标注）
                     ↓ SimResult（组成/温度/duty/收敛状态/假设/WARN/弹窗记录）
            [服务层] FastAPI → Web 界面（类型+理由+假设+澄清+组成表+案例保存）
```

关键工程决策：**先真实、后降级、必标注**。所有任务先尝试真实 HYSYS 建模求解；
仅 COM 侧受限时按白名单降级 Mock，结果中明确写明"非真实 HYSYS 计算值"及原因，
不假装成功。案例保存（.hsc）仅在实际求解成功后执行。

## 3. 探索过程

考核最核心的不确定性在"如何与 HYSYS 通信"。探索按三级推进：

1. **链路自检脚本先行**（`verify_com.py` / `inspect_hysys.py`）：先摸清 COM 对象树
   （Application→SimulationCase→BasisManager/Flowsheet）与真实属性名，再做适配器；
   对象无状态属性，就用 `GetFlowsheetStatus` 状态位 + `IsSolving` 轮询拼出收敛判定。
2. **小步真机实验**：物性包可用性（PR 报错→SRK）、组分真名（注册表 CLSID→安装目录
   SDK 头文件 cid 常量表→COM 逐一暴力验证，挖出 E-Acetate/E-Benzene/Propene 等真名）、
   duty→T_out 曲线扫描（证实光滑单调、绝热点不可解）。
3. **对照实验定位根因**：动力学反应无法挂载的问题，用真机四组对照（跨组分、跨物性包、
   跨相态、是否跳过 BalanceStoichiometry）逐一排除假设，定性为 HYSYS V15 COM 侧限制
   （GUI 手工可解），据此设计降级策略而不是无限纠缠。

## 4. 遇到的问题及解决方式

| 问题 | 根因 | 解决 |
|------|------|------|
| 加酸/酯/醇组分后赋 SRK 物性包报 com_error | HYSYS 对"不推荐"组合弹**模态警告**，卡死 COM 调用 | ① basis 顺序改为"先赋包、后加组分"；② 适配器内置 `_ModalWatchdog` 守护线程（Win32 枚举 #32770 对话框自动点掉），弹窗文字记入结果透出 |
| 绝热重整长期"不收敛" | duty=0 绝热点落在两相产物区**本身不可解**；且写规格后求解器未启动，轮询到过期状态被误读为已收敛 | duty 迭代起点避开 0（1e6/1e7/-1e7/1e8 换挡）；写入与轮询前用 `Solver.CanSolve` 拉低/抬高门控，强制触发一次真实求解 |
| 大进料量时出口温度达不到目标 | duty 迭代上限 1e9 只够中等进料；LLM 自选 10 万 kgmole/h 时 600°C 需 duty≈6e9 | 上限放宽至 1e12、迭代 8→20 次（割线法自校正斜率），失败回退到最接近目标的已解工况并标注 |
| LLM 偶发输出组成之和≠1、漏给反应式 | 免费档模型输出不稳定 | 组成强制按比例归一化（假设中透出）；规则引擎新增"命名反应兜底"（提及知识库别名+反应物齐全→采用知识库反应式），并保留澄清路径 |
| 动力学 CSTR/PFR 无法真实求解 | HYSYS V15 COM 侧限制（见上） | COM 先行尝试 → 失败按白名单降级 Mock，结果标注"非真实 HYSYS 计算值"及精确状态码 |
| 元素守恒但进料缺反应物 → HYSYS 无意义等待 | 解析层只校验了方程守恒 | 解析层增加"反应物必须在进料中"校验，缺失即澄清，不进 HYSYS |
| HYSYS 实例连续跑数十 case 后全线失败 | 实例长会话劣化（COM 单例跨进程持续） | 杀活动实例冷启动即恢复；文档中注明处置方法 |

## 5. 结果

- 考核两个必测场景真机通过：重整 710°C/600°C 双工况（H₂=0.56/0.495，符合重整化学规律）、
  甲苯歧化 50%（甲苯 0.50/苯 0.25/二甲苯 0.25）；通用场景 Gibbs 燃烧、甲醇合成均真机收敛。
- 本地冒烟 92 项断言全过；解析/选择/守恒/降级/保存各环节均有对应测试。
